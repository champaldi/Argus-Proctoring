# Лицо, взгляд и положение головы

Папка `gaze/` содержит самостоятельную часть проекта: MediaPipe Face Mesh,
оценку головы и радужек, число лиц, таймеры и оценку ширины лица в кадре.
Модуль выдаёт пять событий для общего приложения:

| Событие | Условие | Выдержка по умолчанию |
| --- | --- | ---: |
| `gaze_side` | Долгий взгляд/поворот в сторону вне профиля клавиатуры | 3 с |
| `gaze_down` | Долгий взгляд/наклон вниз вне профиля клавиатуры | 5 с |
| `no_face` | Нет обнаруженного лица | 2 с |
| `multiple_faces` | Два или больше обнаруженных лиц | 1 с |
| `too_close_to_camera` | Ширина лица **строго больше 45%** ширины кадра | 3 с |

Одно событие выдаётся один раз за непрерывный эпизод. Возврат к нормальному
состоянию позволяет зарегистрировать следующий эпизод. Большой промежуток
между кадрами сбрасывает таймеры: по умолчанию допускается не более 1 с.

## Установка и самостоятельная демонстрация

Рекомендуется 64-разрядный Python 3.11. Команды выполняются из корня проекта:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r gaze\requirements.txt
.\.venv\Scripts\python.exe -m gaze.demo --camera 0
```

В активном окне демонстрации:

1. **C** — смотреть на рабочий экран до подтверждения настройки.
2. **K** — после настройки экрана смотреть на клавиатуру до подтверждения.
3. **R** — сбросить таймеры, сохранив калибровку.
4. **Q** или **Esc** — завершить демонстрацию.

Поддерживаются английская и русская раскладки: физические клавиши
**C/С**, **K/Л**, **R/К**, **Q/Й**.

Каждый профиль требует минимум 10 валидных измерений при одном лице.
Сбор занимает минимум 2 с и продолжается до 8 с, если обработка медленная
или часть кадров не подходит. Для экрана нужны голова и обе радужки;
для клавиатуры достаточно надёжной головы: при наклоне глаза могут скрываться.
Калибровка использует медианы. Повторная настройка экрана
сбрасывает старый профиль клавиатуры. Настройка экрана и клавиатуры
подтверждена на локальной камере; для каждого нового пользователя её нужно
повторять. Готовые пороги — начальные оценки.

Для сохранения настройки между запусками:
`python -m gaze.demo --profile gaze-profile.json`. Профиль содержит только
медианы головы и радужек. После успешных C/K он сохраняется, при следующем
запуске загружается. При смене человека или положения камеры повторите C/K.

На Windows можно открыть **`gaze/run.cmd`** двойным щелчком. В окне показаны
доля ширины лица и порог, активные таймеры и счётчики всех пяти событий.
Закройте общее приложение перед этой отдельной проверкой, чтобы освободить камеру.

**`gaze/check.cmd`** проверяет версии зависимостей, настоящий Face Mesh,
общий контракт событий и все тесты без открытия камеры. Он ищет готовое
окружение в `.venv/` или `parts/integration-ui/.venv/`; `events.py` должен быть
рядом с `gaze/` либо в `parts/integration-ui/`. Любой пропущенный тест означает,
что полная проверка не подтверждена.

```powershell
python -m gaze.check --host-path "папка_общей_сборки" --report "gaze-report.json"
```

Команда не фотографирует пользователя. Для проверки освещения, очков и
личной зоны клавиатуры после неё нужна живая проверка через демонстрацию.

Можно обработать существующее видео и сохранить только журнал событий:

```powershell
.\.venv\Scripts\python.exe -m gaze.demo --video "test.mp4" --output "events.jsonl"
.\.venv\Scripts\python.exe -m gaze.demo --help
```

Для видео демонстрация использует время кадров по FPS, для камеры — монотонное
время. Окончание видео и ошибка чтения не создают `no_face`. Кадры не зеркалятся;
демонстрация не записывает фотографии или видео. JSONL перезаписывается.

## Подключение к общему приложению

Каноническая точка входа — пакет `gaze`:

```python
from events import ProctorEvent  # Общий events.py приложения.
import gaze

events: list[ProctorEvent] = gaze.analyze(frame)
face_width_ratio: float | None = gaze.get_face_width_ratio()
```

`frame` — уже полученный в общем цикле непустой BGR-кадр `numpy.ndarray`
типа `uint8`, размером `H × W × 3`. Модуль сам не открывает камеру.
`gaze.analyze(frame)` возвращает экземпляры **того же** `ProctorEvent`,
который определён в общем `events.py`. Нормализация подключается при вызове;
свой `events.py` внутри `gaze/` не нужен. В общем адаптере задайте
`PROCTOR_GAZE_MODULE=gaze`. Корневой `gaze_analyzer.py` остаётся совместимым
переходником для прежнего имени модуля.

Подробности для интеграции находятся в [HANDOFF_MAX.md](HANDOFF_MAX.md).

## Устойчивость в общем приложении

`gaze.analyze(frame)` создаёт анализатор с настройками надёжности
(`DEFAULT_GAZE_GAP_SECONDS`, `DEFAULT_MIN_EXTRA_FACE_RATIO`,
`DEFAULT_DOWN_BUDGET_SECONDS` в `analyzer.py`):

- **Частые короткие взгляды вниз.** Телефон на клавиатуре можно читать
  взглядами короче 5 секунд. Поэтому время взглядов вниз суммируется: 15
  секунд за последние 60 дают `gaze_down` с полем `accumulated: true`. После
  события счёт начинается заново, а один взгляд даёт не больше одного события.
  Калибровку клавиатуры в общем приложении включать не нужно: она исключает
  зону клавиатуры из контроля.

- **Короткие провалы сигнала.** Взгляд вниз или в сторону оценивается по
  каждому кадру, и раньше один кадр ниже порога начинал отсчёт заново, поэтому
  реальный взгляд на 5 секунд часто не давал события. Теперь провал до 0,6
  секунды эпизод не сбрасывает. Событие по-прежнему создаётся только на кадре,
  где сигнал есть. На отсутствие лица и на несколько лиц допуск не действует.
- **Лица на фоне.** Лишнее лицо учитывается, только если его ширина не меньше
  0,4 ширины самого крупного лица. Постер или фотография за спиной больше не
  дают «несколько лиц». Основным считается самое крупное лицо. Если ширину
  измерить нельзя, ни одно лицо не отбрасывается.

Обычный `GazeAnalyzer()` без этих аргументов ведёт себя строго, как раньше.

## Оценка ширины лица для интерфейса

`get_face_width_ratio()` возвращает последнюю оценку ширины лица относительно
всего кадра: `0.45` означает **45% ширины**, а не расстояние в сантиметрах.
Используются минимум и максимум нормированных координат X по 36 точкам овала
лица; границы за пределами изображения ограничиваются диапазоном `[0, 1]`.

Если обнаружено ноль/несколько лиц, координаты X недоступны/неконечны
или ширина равна нулю,
значение равно `None`. Показывайте «размер лица недоступен» вместо нуля.
Оценка доступна независимо от успешной оценки позы и радужек. При значении
ровно `0.45` событие близости не возникает; оно требует `ratio > 0.45`
непрерывно не менее трёх наблюдаемых секунд. Профиль клавиатуры его не исключает.

Порог настраивается через `AnalyzerConfig.face_too_close_ratio` и
`face_too_close_seconds`; исходные константы — `FACE_TOO_CLOSE_RATIO = 0.45`
и `FACE_TOO_CLOSE_SECONDS = 3.0`.

## Класс для отдельного потока и проверки

Для каждой камеры/сессии создавайте отдельный экземпляр:
`frame` и `video_seconds` в примере уже получены в вашем цикле обработки.

```python
from gaze import AnalyzerConfig, GazeAnalyzer

config = AnalyzerConfig(face_too_close_ratio=0.45, face_too_close_seconds=3.0)
with GazeAnalyzer(config) as analyzer:
    raw_events = analyzer.analyze(frame, timestamp=video_seconds)
    ratio = analyzer.get_face_width_ratio()
    result = analyzer.last_result
```

Метод класса возвращает `list[dict]` для самостоятельной демонстрации
и отладки; общий интерфейс `gaze.analyze()` возвращает `list[ProctorEvent]`.
Метрики последнего кадра находятся в `AnalysisResult`: `face_count`,
`face_width_ratio`, `metrics`, `signals`, `events`, `elapsed`.

Поза головы и радужки оцениваются независимо. `metrics.head_pose` может быть
`None`, когда положение головы неизвестно, но обе радужки распознаны надёжно.
В таком кадре возможен взгляд вниз/в сторону по глазам. При неизвестных
и голове, и радужках `metrics` равен `None`; нулевые углы не подставляются.
Для калибровки используйте `is_calibration_sample_valid()`.

Для выяснения причины несрабатывания доступны `analyzer.get_diagnostics()`
и `gaze.get_diagnostics()`. Они показывают исходные/сглаженные измерения,
профили, нахождение в зоне клавиатуры, отложенные и уже выданные события.
Демонстрация показывает эти сведения в окне. При необходимости можно
сохранить только числовой журнал: `python -m gaze.demo --telemetry trace.jsonl`.
Фотографии и видео в этот журнал не записываются.

Временные метки класса задаются в секундах исходного видео или одной
монотонной шкалы; они должны быть конечными и не убывать. Повторная метка
не увеличивает таймер. Неверный кадр сбрасывает состояние и вызывает ошибку,
а не событие отсутствия лица. Короткое моргание до 0.3 с сохраняет начавшийся
эпизод по радужкам, но его событие откладывается до открытия глаз.

`calibrate(samples, target="screen" | "keyboard")` задаёт профили.
Углы головы оцениваются приближённо: начальные пороги — 25° в сторону и 35°
вниз. После настройки обоих профилей порог вниз учитывает зону клавиатуры:
`min(head_down_degrees, max(calibrated_head_down_degrees,
keyboard_pitch - screen_pitch + keyboard_pitch_tolerance + keyboard_down_margin_degrees))`.
Начальные значения нижней границы и запаса — 20° и 3°; комбинированный
порог головы ограничивается полученным значением. Без профиля клавиатуры
сохраняется исходный порог 35°. Это позволяет обнаруживать естественный
наклон раньше, чем лицо исчезнет из кадра. Клавиатура исключается по допускам головы и, если доступны в профиле и
текущем кадре, обеих координат радужек. Без надёжных радужек используется
только выученная зона головы; направление взгляда внутри неё не различается.
Свежий возврат к экрану прерывает эпизод, даже если медиана ещё содержит
старые измерения. Потеря радужек дольше 0.3 с прерывает эпизод по глазам
и при их последующем восстановлении; подтверждённый поворот головы сохраняется.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s gaze/tests -v
```

Автоматические проверки не заменяют проверку реального освещения, очков,
обычного набора текста, ухода из кадра, второго лица и приближения к камере.

## Компоненты и ограничения

Используются MediaPipe 0.10.21 (лицо/радужки), OpenCV contrib 4.11.0.86
(изображения и поза), NumPy 1.26.4 (геометрия), JAX/JAXlib 0.4.38
(совместимые зависимости MediaPipe). Старый API `mediapipe.solutions` закреплён
версией; отдельный файл `face_landmarker.task` не нужен.

Ширина лица зависит от камеры, положения и поворота головы. Она служит
приближённым признаком близости. Оценка взгляда не отличает клавиатуру от
телефона в том же направлении. `no_face` означает отсутствие обнаружения,
а `multiple_faces` не определяет личность человека. Число обнаружений ограничено
`max_num_faces` (по умолчанию 3). Это подозрительные события
для проверки преподавателем. Телефон, защита среды, интерфейс и база данных
относятся к остальным частям приложения.

При разработке кода, тестов и документации использовался AI-помощник Codex;
сведения об этом и готовых компонентах нужно сохранить в материалах команды.
