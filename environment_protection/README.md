# Защита окружения — часть 3

Модуль для Windows, совместимый с существующим `core.security.SecurityAdapter`.
Публичные функции: `enable(callback=None)` и `disable()`. Импорт ничего не
блокирует, не открывает камеру и не загружает модели.

## Что добавлено

- `keyboard`: блокировка Alt+Tab, обеих Win, Ctrl+C/V и PrtScn.
  C/V определяются по физическим клавишам и работают в русской раскладке.
  Левые и правые модификаторы учитываются отдельно.
- Дополнительно блокируются Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+PageUp/PageDown,
  Ctrl+1…9 для переключения вкладок с клавиатуры.
- `pywin32`: проверка активного окна каждые 0,2 с, событие при уходе фокуса
  и попытка вернуть окно теста. Его собственные диалоговые окна разрешены;
  постороннее окно того же процесса не получает автоматического разрешения.
- `psutil`: проверка браузеров и мессенджеров каждые 2 с. Процесс теста и его
  дочерние процессы исключаются. Дочерние процессы одного браузера объединяются.
  Для защиты внешнего браузера передайте его HWND явно.
- Процессы только регистрируются в журнале; принудительного завершения нет.
  Доступ к сторонним окнам ограничивается контролем фокуса.

Список имён процессов находится в `ProtectionConfig.blocked_process_names`:
Chrome, Edge, Firefox, Opera, Brave, Vivaldi, browser.exe, Telegram, Discord,
Slack, WhatsApp, Teams и Skype. Это проверка имён, а не идентификация любого
возможного приложения. Несколько окон/вкладок внутри разрешённого браузерного
процесса нельзя отличить одним `psutil`.

## Подключение в общий проект

Положить папку `environment_protection` рядом с `main.py` и `events.py`.
В `codex/integration-ui` ничего дополнительно менять не требуется:

```python
# Уже реализовано в core/security.py:
enable(self._receive)
# При завершении теста или закрытии окна:
disable()
```

В `config.py` уже указано имя `environment_protection`. При необходимости:

```powershell
$env:PROCTOR_SECURITY_MODULE = "environment_protection"
```

Зависимости `keyboard`, `pywin32`, `psutil` уже присутствуют в общем
`requirements.txt`. Рекомендуемый runtime команды — 64-разрядный Python 3.11.

Обычное использование вне адаптера:

```python
import environment_protection as protection

# Вызывать после показа окна теста, в основном потоке приложения.
try:
    protection.enable(on_event)  # on_event принимает один словарь
    run_test_event_loop()
finally:
    protection.disable()
```

Если в текущем процессе несколько отдельных окон, указать нужное явно:

```python
protection.enable(on_event, hwnd=int(test_window.winId()))
```

Автоматический выбор ищет окно текущего Python-процесса. Чужое активное окно,
например терминал или редактор, никогда не принимается за окно теста.
Вызов до появления окна выдаёт понятную ошибку до установки перехвата.

`enable()` без callback поддерживается: события можно читать через
`drain_events()`. При callback события поступают из отдельного потока;
используйте очередь или сигнал Qt для обновления интерфейса.
Существующий `SecurityAdapter` уже нормализует их в общий `ProctorEvent`.
Обработчик должен быстро возвращаться; очередь ограничена 256 событиями.

## Контракт событий

```json
{
  "type": "hotkey_blocked",
  "source": "security",
  "occurred_at": "2026-10-06T10:00:00+00:00",
  "details": {"hotkey": "ctrl+c"}
}
```

- `hotkey_blocked`: `details.hotkey`; одно событие на нажатие без автоповтора.
- `window_switched`: `previous_hwnd`, `target_hwnd`, `focus_restored`.
  При неудачном восстановлении одно событие на непрерывный уход из окна;
  попытки возврата повторяются не чаще раза в 0,5 с.
- `suspicious_process`: `details.processes` — список `{pid, name, create_time}`,
  `count` и `action="reported"`. Новые процессы одного сканирования объединены
  в одно событие, чтобы общий фильтр повторов не терял остальные процессы.
  Повторное появление процесса или переиспользование PID — новое наблюдение.

Все три типа уже есть в `events.py`, UI, настройках риска и хранилище.
При штатном отключении накопленные события передаются обработчику.
Зависший обработчик не задерживает снятие блокировок; ожидание его потока
ограничено 0,25 с, поэтому доставка оставшихся событий при зависании не гарантируется.

## Выключение и ограничения демо

1. **Ctrl+Alt+F12** немедленно прекращает подавление клавиш; затем снимается
   наш перехват и останавливается наблюдение. Завершать Python для этого не нужно.
2. `disable()` сначала разрешает все клавиши, затем удаляет только наш hook.
   Повторный вызов безопасен; ошибка снятия hook доступна через `status()`.
3. Закрытие окна теста, ошибка наблюдения или обработчика событий, переполнение
   очереди и истечение таймера выключают защиту.
4. Независимый поток автоматически выключает защиту через **15 минут**.
   Для другой длительности передайте `ProtectionConfig(max_seconds=...)`
   непосредственно в `enable`; значение должно быть конечным и положительным.
5. `atexit` вызывает `disable()` при обычном завершении Python. При аварийном
   завершении процесса Windows удаляет его перехват. Системные политики,
   реестр, службы и настройки клавиатуры не изменяются.

Это демонстрационный ограничитель, а не системный киоск. Ctrl+Alt+Del не
перехватывается; аварийное отключение намеренно доступно. Ошибка Windows при
`SetForegroundWindow` возможна: `focus_restored=false` честно отражает отказ.
Короткие переключения между опросами могут быть не замечены.
Переключение вкладки мышью внутри одного браузерного окна не определяется
проверкой HWND: для полного запрета нужен киоск/ограничение в самом браузере.
В текущем PySide6-тесте браузерных вкладок нет.

Адаптер команды показывает статус только в момент включения. После аварийного
выключения или таймера его подпись в UI может остаться прежней; актуальное
состояние возвращает `environment_protection.status()`. Наше демо опрашивает
его каждые 100 мс. Это описано для автора UI; исходный интерфейс не изменён.

Общий `EventPipeline` намеренно фильтрует близкие события одного типа:
0,25 с для клавиш, 1 с для окна, 10 с для процессов (в старой ветке detection
первые два интервала — 0,5 и 2 с). Поэтому журнал может содержать меньше
событий, чем callback защиты, включая разные процессы из соседних сканирований.

## Запуск и проверка

В созданной локальной папке проекта среда `.venv` уже подготовлена:

```powershell
cd D:\Project\remotte_test\team-project
.\.venv\Scripts\python.exe -m environment_protection.demo --seconds 60
```

Защита в демо включается только кнопкой. Доступны отдельная крупная кнопка
выключения, поле для набора текста, журнал и актуальный статус.
Проверить клавиши, переключение мышью на другое окно, возврат фокуса,
Ctrl+Alt+F12, закрытие демо и повторное включение. После выключения проверить,
что Alt+Tab, Win и копирование снова работают.

Для новой машины:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r environment_protection/requirements.txt
```

Общее приложение после установки общего `requirements.txt` запускается
`.\.venv\Scripts\python.exe main.py`. Оно включает защиту автоматически,
а модели могут загрузить веса при первом запуске.

Автоматические проверки не устанавливают реальных перехватов:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m unittest discover -s detection -p "test_*.py" -v
```

Проверены обычные/правые/заранее зажатые модификаторы, русская раскладка,
освобождение после ошибок, таймер и аварийная комбинация, зависший callback,
повторное включение, очередь при завершении, дерево процессов, отказ возврата
фокуса, собственные диалоги и путь SecurityAdapter → EventPipeline → SQLite.
Автоматическая проверка не заменяет ручное демо с реальными клавишами и окнами.

## Передача своей части

Для публикации только своей ветки после проверки:

```powershell
git push -u origin feature/environment-protection
```

файла тестов. Файлы `core/`, `ui/`, `events.py`, gaze и detection в нашей
работе не изменены. Ветки сокомандников не требуется перезаписывать.

## Источники и готовые компоненты

- [keyboard 0.13.5](https://github.com/boppreh/keyboard): глобальный перехват клавиш Windows.
- [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow): условия и ограничения возврата фокуса.
- [GetAncestor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getancestor): принадлежность диалогов окну теста.
- [psutil](https://psutil.io/api/): процессы, PID, родительские процессы, время запуска.
