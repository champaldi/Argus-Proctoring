# Взгляд и положение головы — модуль для кейса № 3

Реализован выделенный пункт: локальный анализ кадров с четырьмя событиями
`gaze_down`, `gaze_side`, `no_face`, `multiple_faces`. На входе — кадр OpenCV,
на выходе — список новых событий, пригодный для журнала общей системы.

MediaPipe Face Mesh получает точки лица и радужек с `refine_landmarks=True`;
OpenCV `solvePnP` оценивает положение головы по соответствиям точек лица
и трёхмерного шаблона. Положение радужек относительно глаз служит приближением
направления взгляда. Это не определение точной точки на экране.
Используется закреплённый старый API `mediapipe.solutions.face_mesh`:
`mediapipe==0.10.21`. Отдельно скачивать `face_landmarker.task` не нужно.

## Установка и запуск

Нужен 64-разрядный Python 3.10–3.12. Для Windows из папки проекта:

Если `.venv` уже создано и зависимости установлены, выполните только команду
запуска `demo.py`. На новом компьютере выполните все три команды.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe demo.py --camera 0
```

Если основная камера имеет другой индекс, замените `0` на `1` или `2`.
Камера открывается при явном запуске демонстрации. При импорте модуля камера
не открывается. Для видео и сохранения только журнала событий:

```powershell
.\.venv\Scripts\python.exe demo.py --video "test.mp4" --output "events.jsonl"
.\.venv\Scripts\python.exe demo.py --camera 0 --side-seconds 3 --down-seconds 5
.\.venv\Scripts\python.exe demo.py --help
```

Видеофайл должен сообщать корректный FPS. Время рассчитывается по номеру кадра
и FPS, поэтому ускоренная обработка не сокращает длительность эпизодов.
Для видео с переменным FPS передавайте в модуль реальные временные метки кадров
из своего декодера. Для камеры демонстрация использует монотонное время
от начала запуска. Завершение файла и ошибка чтения камеры останавливают
демонстрацию; они не создают `no_face`.

`--output` создаёт/перезаписывает UTF-8 JSONL: одна строка JSON на событие.
События также выводятся в консоль. Кадры, фотографии и видеозапись не сохраняются.
Предпросмотр не зеркальный; анализ получает исходный кадр.

## Калибровка и проверка с камерой

Клавиши работают, когда окно предпросмотра активно:

1. Сядьте в обычное положение, обеспечьте ровный свет и видимость обоих глаз.
2. Нажмите **C** и около двух секунд смотрите в центр рабочего экрана.
3. Нажмите **K** и около двух секунд смотрите на клавиатуру так, как при наборе.
4. **R** сбрасывает таймеры и сглаживание, сохраняя калибровку;
   **Q** или **Esc** завершает работу.

Для каждого профиля требуется минимум 10 кадров с одним лицом и доступными
оценками радужек. Если кадры не собраны, повторите калибровку. Профиль клавиатуры
задаётся после профиля экрана. Повторная калибровка экрана требует снова
откалибровать клавиатуру. Профили хранятся в памяти текущего анализатора.

Перед демонстрацией проверяйте поведение на реальном человеке:

| Проверка | Ожидаемый результат |
| --- | --- |
| Смотреть на экран, моргать, слегка менять позу | Нет событий взгляда |
| Набирать текст, коротко смотреть на клавиатуру | Нет событий взгляда |
| Смотреть на откалиброванную клавиатуру дольше 5 с | Нет событий взгляда внутри допусков профиля |
| Повернуть голову влево/вправо либо долго смотреть в сторону вне профиля клавиатуры | Один `gaze_side` после 3 с |
| Смотреть вниз в область вне профиля клавиатуры | Один `gaze_down` после 5 с |
| Уйти из кадра | Один `no_face` после 2 с |
| Добавить второе лицо | Один `multiple_faces` после 1 с |
| Вернуться в нормальное положение и повторить эпизод | Новое событие после новой выдержки |

Проверка на камере пользователя и подбор порогов ещё не выполнены.
Запишите наблюдения и при необходимости меняйте `AnalyzerConfig`. Числа ниже —
начальные оценки для настройки, а не измеренная точность и не универсальные
пороги. Проверяйте разные камеры, освещение, очки и расстояния до экрана.

## Интерфейс для интеграции

Рекомендуется отдельный экземпляр на каждый независимый поток видео:

```python
import cv2

from gaze_analyzer import AnalyzerConfig, GazeAnalyzer

capture = cv2.VideoCapture(0)
try:
    with GazeAnalyzer(AnalyzerConfig()) as analyzer:
        while True:
            ok, frame = capture.read()
            if not ok:
                break
            for event in analyzer.analyze(frame):
                print(event)  # Передать в журнал/очередь общей системы.
finally:
    capture.release()
```

Для уже существующего цикла с одним потоком доступна короткая форма:

```python
from gaze_analyzer import analyze, reset_default_analyzer

try:
    events = analyze(frame)  # frame уже получен в вашем цикле захвата.
finally:
    reset_default_analyzer()  # Закрыть экземпляр по умолчанию после потока.
```

`GazeAnalyzer.analyze(frame, *, timestamp=None) -> list[dict]` принимает
непустой незеркальный BGR-кадр `numpy.ndarray` типа `uint8` с тремя каналами.
Без `timestamp` используется
`time.monotonic()`. Для записи передавайте секунды времени исходного видео,
а не время его обработки. Временные метки должны быть конечными и не убывать;
повторная метка допустима, но не увеличивает длительность эпизода.
Один экземпляр хранит состояние одного потока; не смешивайте кадры разных камер
и разные шкалы времени.
Неверный формат кадра сбрасывает таймеры и `last_result`, затем вызывает
`ValueError`; ошибка входных данных не превращается в `no_face`.

Пример события:

```json
{
  "type": "gaze_side",
  "duration": 3.2,
  "timestamp": 12.4,
  "started_at": 9.2,
  "face_count": 1,
  "head_pose": {"pitch": 2.1, "yaw": 31.8, "roll": -1.2}
}
```

| Событие | Условие |
| --- | --- |
| `gaze_side` | Голова или радужки достаточно долго отклонены в сторону вне профиля клавиатуры |
| `gaze_down` | Наклон головы/оценка радужек указывают вниз; профиль клавиатуры исключается |
| `no_face` | Детектор достаточно долго возвращает ноль лиц |
| `multiple_faces` | Детектор достаточно долго возвращает два или больше лиц |

`duration` — наблюдаемая длительность эпизода к моменту срабатывания,
`timestamp` — метка текущего кадра, `started_at` — метка начала эпизода.
Это секунды в выбранной шкале, не дата и время UTC. `head_pose` добавляется,
когда доступна оценка головы. Левое и правое направления объединены
в `gaze_side`.

Каждое событие выдаётся **один раз за непрерывный эпизод** при достижении
временного порога и доступности подтверждающего измерения.
Возврат к нормальному состоянию сбрасывает
соответствующий таймер. Отсутствие лица и несколько лиц приоритетнее оценки
взгляда; при них не используется взгляд случайно выбранного человека.
Пропуск между кадрами больше `max_sample_gap_seconds` сбрасывает накопление:
пауза обработки не считается наблюдаемым нарушением. Короткое моргание
до `iris_missing_grace_seconds` сохраняет уже начавшийся эпизод по радужкам,
но его событие откладывается до открытия глаз. Более долгое отсутствие
оценки радужек сбрасывает таймеры, основанные только на них; таймеры по
положению головы продолжают работать.

После обработки `analyzer.last_result` содержит:

- `face_count` — число обнаруженных лиц;
- `metrics` — `FaceMetrics` для одного лица либо `None`;
- `signals` — текущие сигналы до истечения таймеров;
- `events` — новые события текущего кадра;
- `elapsed` — накопленные секунды по активным типам события; неактивные отсутствуют.

`FaceMetrics.head_pose` содержит `pitch`, `yaw`, `roll` в градусах:
положительный `pitch` означает наклон вниз, `yaw` — поворот влево на изображении
(вправо для студента при незеркальной камере), `roll` — наклон по часовой стрелке.
Параметры камеры приближённые; углы не являются точным измерением калиброванной камеры.
`iris_x` и `iris_y` — относительное положение радужек внутри глаз
(нейтральное значение примерно `0.5`); при моргании это `None`.
`iris_centers` — пары нормированных координат `(x, y)` для отрисовки.
Это приближённая оценка радужки, а не точная сегментация зрачка.

Для калибровки в собственном интерфейсе собирайте доступные `FaceMetrics`
при одном лице, затем вызывайте:

```python
analyzer.calibrate(screen_samples, target="screen")
analyzer.calibrate(keyboard_samples, target="keyboard")
```

Используются медианные значения, чтобы отдельные шумные кадры меньше влияли
на профиль. `analyzer.reset()` сохраняет калибровку. Контекстный менеджер
или `analyzer.close()` освобождает ресурсы Face Mesh.

## Начальные параметры

Передавайте нужные поля в `AnalyzerConfig(...)`:

| Поле | По умолчанию | Назначение |
| --- | ---: | --- |
| `gaze_side_seconds` | 3.0 с | Выдержка взгляда в сторону |
| `gaze_down_seconds` | 5.0 с | Выдержка взгляда вниз |
| `no_face_seconds` | 2.0 с | Выдержка отсутствия лица |
| `multiple_faces_seconds` | 1.0 с | Выдержка нескольких лиц |
| `head_side_degrees` | 25° | Поворот головы в сторону |
| `head_down_degrees` | 35° | Наклон головы вниз |
| `combined_down_degrees` | 25° | Наклон при совместной проверке с радужками |
| `iris_side_threshold` | 0.18 | Боковое смещение от профиля экрана |
| `iris_down_threshold` | 0.30 | Смещение вниз от профиля экрана |
| `combined_iris_down_threshold` | 0.16 | Смещение при совместной проверке с головой |
| `keyboard_pitch_tolerance` | 10° | Допуск наклона к профилю клавиатуры |
| `keyboard_yaw_tolerance` | 10° | Допуск поворота к профилю клавиатуры |
| `keyboard_iris_tolerance` | 0.15 | Допуск положения радужек к профилю клавиатуры |
| `min_eye_open_ratio` | 0.12 | Минимальная открытость глаза для оценки радужки |
| `iris_missing_grace_seconds` | 0.3 с | Допустимый краткий пропуск оценки радужек в начавшемся эпизоде |
| `smoothing_window` | 3 кадра | Медианное сглаживание измерений |
| `max_sample_gap_seconds` | 1.0 с | Максимальный промежуток непрерывного наблюдения |
| `max_num_faces` | 3 | Ограничение числа лиц детектора |
| `calibration_min_samples` | 10 | Минимум валидных измерений в профиле |

Короткий взгляд вниз защищён выдержкой 5 с. Калибровка дополнительно
исключает `gaze_down` и `gaze_side` внутри выученной области клавиатуры:
проверяются наклон и поворот головы, а также обе координаты радужек.
Взгляд в сторону за пределами этой области продолжает отслеживаться.
При смене рабочего места калибровку нужно повторить.

## Ограничения и связь с документами

Модуль формирует подозрительные события для проверки, а не доказательство
списывания. Закрытое лицо, сильный поворот, блики на очках и плохой свет
снижают надёжность. `no_face` означает отсутствие обнаруженного лица,
а не подтверждённый уход студента. `multiple_faces` не определяет личность
постороннего. Детектор ограничен `max_num_faces`: значение `3` может означать
«три или больше», а не точное число людей в помещении.

Камера и геометрия взгляда не позволяют отличить клавиатуру от телефона,
если они находятся в том же направлении. Профиль клавиатуры может скрыть
такой эпизод. Обнаружение телефона — отдельная часть проекта.
Распознавание личности, сервер, кабинет преподавателя и общий отчёт
в этом модуле не реализованы.

Основание: «Кейс №3 КРУ и Qostanai Hub рус.pdf», стр. 2, п. 2.2:
длительный взгляд вниз или в сторону, присутствие студента и появление
второго лица. В разделе 3 предложен Face Mesh для взгляда/головы и YOLO
для телефона/лиц. Здесь реализована только назначенная часть MediaPipe.
Конкретные секунды, угловые пороги, исключение клавиатуры и имена событий
в PDF не заданы: это параметры реализации по заданию пользователя.
Раздел 4 кейса требует общий работающий локальный прототип всех трёх частей;
этот модуль нужно интегрировать с работой остальных участников.

«Положение на русском языке.pdf», стр. 4, п. 5.8 разрешает библиотеки
и публичные модели при указании названия и назначения; п. 6.2 требует
прототип/демонстрацию и краткое описание архитектуры, технологий, внешних
компонентов и ограничений. Стр. 5, п. 6.4 разрешает AI с раскрытием использования
и пониманием кода командой. Сведения ниже нужно сохранить в материалах команды
и дополнить информацией об остальных частях.

Использованные готовые компоненты: **MediaPipe 0.10.21** (модель лица/радужек),
**OpenCV contrib 4.11.0.86** (видео, вычисление позы, предпросмотр),
**NumPy 1.26.4** (массивы и геометрические вычисления).
При подготовке кода, документации и проверок использовался **AI-помощник Codex**;
эту информацию следует сохранить в материалах команды.
Пороговые правила и таймеры не являются собственной обученной нейросетью.

Дополнительно настоящий Face Mesh проверен на публичном тестовом портрете
MediaPipe: одно лицо с конечными оценками головы/радужек без событий,
композиции из двух и трёх лиц с одним `multiple_faces` после 1 с и пустые кадры
с одним `no_face` после 2 с. Это проверка работоспособности, а не оценка точности.

Автоматические проверки не заменяют приведённую выше проверку камеры
и подбор порогов на реальных условиях.
