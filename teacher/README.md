# Панель преподавателя

Из корня проекта после установки общих зависимостей:

```powershell
python -m teacher
```

Панель читает сессии из `PROCTOR_DATA_DIR/proctoring.db` (по умолчанию
`data/proctoring.db`). Исходная база открывается только для чтения. Решения,
комментарии и отметки ложных срабатываний хранятся отдельно в
`teacher/state/reviews.db`.

На странице сессии панель показывает:

- имя студента из стартового окна теста и номер сессии (личность по кадрам
  событий сверяет преподаватель, распознавание лиц не используется);
- заключение системы — короткий текст по правилам из записанных событий
  (`teacher/conclusion.py`); это подсказка, а не вердикт;
- кнопку «Сохранить отчёт»: отчёт по сессии одним HTML-файлом с кадрами,
  таймлайном и решением преподавателя (`teacher/report.py`). Файл открывается
  в любом браузере и печатается в PDF.

Условия экзамена: в карточке сессии преподаватель отмечает, что на этом
экзамене разрешено — смотреть вниз (клавиатура, черновик) или пользоваться
материалами сбоку и вторым экраном. События разрешённого типа остаются в
журнале с пометкой «разрешено», но не входят в риск, сводку и правила
корреляции; в HTML-отчёте указаны условия и число разрешённых событий.
Телефон, второе лицо, удалённый доступ и запрещённые программы разрешить
нельзя. Условия хранятся вместе с решениями в `teacher/state/reviews.db`.

Учебные данные:

```powershell
python -m teacher.seed_demo
python -m teacher --demo
```

Генератор создаёт базу того же формата и кадры-заглушки в
`teacher/demo_data/`. Повторный запуск обновляет только шесть demo-сессий.
Для другой базы можно указать `--db ПУТЬ`, для отдельного файла решений —
`--reviews ПУТЬ`.

Тесты:

```powershell
python -m unittest discover -s teacher -p "test_*.py" -v
```

Имя студента приложение записывает в `metadata_json` (`student_name`). Если
его нет (старые сессии), панель покажет начало идентификатора сессии. Длительность берётся из `duration`
или `duration_seconds` в событии; если поле отсутствует, она неизвестна.
Пересчёт риска повторяет правила `core.risk` по времени событий и исключает
отмеченные ложные срабатывания.

## Правила корреляции

Кроме уровня риска, заключение показывает сработавшие правила (`teacher/rules.py`).
Правило смотрит на сочетание событий во времени, как правило детектирования в
SIEM, и относит его к одному из двух уровней:

- **Признаки нарушения (V1–V6)**: сочетание, которое трудно объяснить
  случайностью. Например, V2 «Списывание с телефона» — телефон в кадре и взгляд
  вниз в пределах 30 секунд; V1 — телефон наведён на экран; V3 — удалённая сессия.
- **Подозрительно (S1–S9)**: одиночный сильный сигнал или повторение слабого.
  Например, S2 — три долгих взгляда вниз за 5 минут; S1 — телефон в кадре без
  других признаков.

Одиночный взгляд вниз или в сторону остаётся наблюдением и правило не запускает.
Правила работают по записанному журналу: если преподаватель снимает событие как
ошибочное, связанное с ним правило перестаёт срабатывать. Решение по-прежнему
принимает преподаватель.
